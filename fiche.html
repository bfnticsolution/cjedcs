3. Objectifs par jour (vue synthétique)

Jour 1 — Premiers pas

Comprendre le Web · Installer VS Code · Écrire son premier index.html

  • À la fin, chaque apprenant sait : expliquer Internet/Web/site/page, installer VS Code et Live Server, générer du HTML avec DeepSeek, afficher sa première page
  • Exercice final : page de présentation personnelle (h1 + p + img + ul + a)
  • Devoir : refaire le fichier index.html de zéro

Jour 2 — HTML approfondi

Titres hiérarchisés · Images · Liens · Listes · Navigation entre pages

  • À la fin : hiérarchiser les titres h1-h6, insérer images et liens, créer 3 pages reliées, utiliser les balises sémantiques
  • Exercice final : page « À propos » structurée
  • Devoir : 3 images + 2 textes courts sur son sujet

Jour 3 — CSS mise en page

Sélecteurs · Couleurs · Polices · Box model · Flexbox

  • À la fin : relier un style.css externe, écrire des règles CSS, contrôler couleurs/polices/marges, disposer 2 blocs côte à côte
  • Exercice final : appliquer le style à tout le site
  • Devoir : refaire un style.css de zéro sur une page

Jour 4 — CSS avancé & galerie

Variables CSS · Grid · Cartes · Ombres · Galerie responsive · Media queries

  • À la fin : utiliser les variables CSS, créer une grille Grid, concevoir des cartes modernes, galerie responsive
  • Exercice final : galerie de 6 photos responsive
  • Devoir : refaire une galerie de zéro

Jour 5 — Site multi-pages

Navigation commune · Fil d'Ariane · Footer pro · Page 404 · Maillage

  • À la fin : uniformiser le menu, signaler la page active, structurer l'arborescence, créer footer et page 404
  • Exercice final : créer une page « Équipe » intégrée
  • Devoir : ajouter une 7e page libre (blog, tarifs, FAQ)

Jour 6 — Formulaires & JavaScript

Form HTML · Types de champs · Style · DOM · Validation

  • À la fin : créer un formulaire complet, le styliser, écrire du JS simple, manipuler le DOM, valider un formulaire
  • Exercice final : formulaire complet avec validation JS
  • Devoir : tester le formulaire sur mobile

Jour 7 — Mise en ligne

GitHub · Git · GitHub Pages · Publication · Présentation

  • À la fin : créer un compte GitHub, publier le site, tester en ligne, présenter son projet
  • Exercice final : présentation de 4 minutes devant le groupe
  • Livrable : URL du site publié + attestation de fin de formation

4. Gestion d'un groupe hétérogène

Trois profils dans la salle

ProfilSignesStratégie
Débutant total N'a jamais touché un éditeur de code, hésite sur les dossiers, tape lentement Rassurer, accompagner physiquement, lui donner des consignes très détaillées (slide par slide), l'inciter à noter
Intermédiaire A déjà utilisé Word/Excel, sait gérer des fichiers, avance vite sur les manipulations Laisser avancer, proposer des défis bonus, l'inciter à aider les débutants
Avancé Connaît déjà un peu HTML ou CSS, s'ennuie sur les slides de base Lui confier des missions (aider les autres, préparer un exemple), lui proposer d'aller plus loin sur chaque exercice

Techniques de gestion

  • Binômes débutant + intermédiaire : le débutant progresse, l'intermédiaire consolide
  • Rythme : ne jamais laisser un débutant plus de 3 minutes bloqué. Circuler en permanence.
  • Pauses actives : pendant les 5 min de pause, demander à chacun ce qu'il a appris aujourd'hui
  • Valorisation : montrer les réussites de chacun. Un débutant qui publie sa première page mérite un applaudissement.
  • Exercice final : faire circuler les apprenants pour voir les écrans des autres. L'émulation fonctionne mieux que la comparaison.

6. Réponses types aux questions fréquentes

« Est-ce que c'est trop dur pour moi ? » Cette formation part de zéro. Si vous savez utiliser un navigateur et gérer des dossiers, vous savez assez. Nous avançons par petits pas, avec beaucoup de pratique.
« Pourquoi mon CSS ne s'applique pas ? » Ouvrez la console (F12). Vérifiez trois choses : (1) le fichier style.css existe, (2) la balise <link> est bien écrite, (3) le chemin est correct. 90 % des cas viennent de là.
« Mon image ne s'affiche pas. » Trois causes fréquentes : le nom du fichier ne correspond pas exactement (majuscules/minuscules comptent), l'image n'est pas dans le bon dossier, le chemin utilise des antislashs (\) au lieu de slashs (/).
« Je ne comprends rien au JavaScript. » C'est normal. Le JavaScript est un langage, il s'apprend sur plusieurs mois. Aujourd'hui, nous ne faisons que les bases : réagir à un clic, lire un champ, valider un formulaire. C'est tout.
« Dois-je acheter un hébergement pour publier mon site ? » Non. GitHub Pages est gratuit à vie pour les sites statiques (HTML + CSS + JS). Il faudra un hébergement payant plus tard, uniquement si vous ajoutez du PHP ou une base de données.
« J'ai oublié mon mot de passe GitHub. » Allez sur github.com → Sign in → Forgot password. GitHub envoie un lien de réinitialisation par email. Notez le nouveau mot de passe dans un carnet ou un gestionnaire.
« Puis-je utiliser les images de Google ? » Pour un site personnel ou un exercice : oui, en pratique. Pour un site professionnel publié : il faut utiliser des images libres de droits (Unsplash, Pexels, Pixabay) ou acheter les droits.
« Et si je n'ai pas d'ordinateur ? » Plusieurs solutions : partager le PC d'un camarade en binôme, utiliser un ordinateur du centre, ou travailler sur mobile avec un éditeur en ligne (CodePen, StackBlitz) pour suivre les exercices.
« Est-ce que je peux refaire un site pour moi après la formation ? » Absolument, et c'est même recommandé. La formation vous donne la méthode. Le deuxième site se fait en moitié moins de temps. Le troisième, en un après-midi.
« Pourquoi on utilise l'IA ? Ça ne va pas me rendre paresseux ? » L'IA est un assistant, pas un remplaçant. Elle écrit du code, mais vous devez le lire, le comprendre, l'adapter. Si vous ne comprenez pas une ligne, vous ne maîtrisez rien. La règle : ne jamais copier sans lire.

7. Points de vigilance

Ne jamais avancer sans vérifier. À la fin de chaque bloc, faites un tour rapide : tous les apprenants ont-ils bien fait l'étape précédente ? Sinon, corrigez avant d'avancer.
Ne jamais laisser un apprenant bloqué seul plus de 3 minutes. Le découragement s'installe vite. Circulez en permanence pendant les phases de pratique.
Ne jamais promettre ce qui n'est pas dans la formation. Si une question dépasse le cadre, notez-la et répondez à la séance suivante. L'honnêteté renforce la confiance.
Attention aux mots de passe GitHub. Faites noter à chaque apprenant son email, son nom d'utilisateur et son mot de passe GitHub dans un carnet. Sans cela, les sites publiés seront perdus.
Attention aux chemins d'images. À la fin du Jour 2, vérifiez que tous les chemins d'images sont relatifs (ex : images/photo.jpg) et non absolus (ex : C:\Users\hp\Bureau\photo.jpg).

8. Après la formation

  • Remise d'attestation : uniquement aux apprenants ayant suivi les 7 séances et présenté leur projet
  • Envoi du récapitulatif : par WhatsApp, lien vers le site publié et le groupe WhatsApp du centre
  • Suivi : proposer un rendez-vous 1 mois après pour voir les progrès
  • Orientation : ceux qui veulent aller plus loin peuvent suivre la formation PHP/MySQL (niveau intermédiaire)
  • Recommandation : ouvrir un compte GitHub à tous ceux qui n'en ont pas encore
